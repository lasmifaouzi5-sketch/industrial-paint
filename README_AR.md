# Industrial Paint — مراجعة v19 (14/11/2026)

## حالة الحزمة — v20 Netlify release
تم تنفيذ ترحيل قاعدة البيانات بنجاح على مشروع Supabase المرتبط بالتطبيق بتاريخ 14/11/2026، وسُجلت هجرتا قاعدة البيانات:
- `industrial_paint_v19_back_chemical_fix`
- `industrial_paint_v19_restrict_new_admin_rpcs`

تم التحقق من وجود العمود `layer_consumptions.chemical_barrel_id`، ووجود دوال RPC المطلوبة، ومنع دور `anon` من تنفيذ دوال الإدارة الجديدة مع الإبقاء على صلاحية `authenticated`. كما بقي رصيد EP-3189 للبرميل 003 يساوي 150 kg (200 kg افتتاحي - 50 kg حركة OUT موجودة)، ولم تُحذف أي حركة أو سجل.

**مهم:** لم ننفذ إنتاجاً تجريبياً أو حركات استهلاك/عكس في قاعدة الإنتاج حتى لا نغيّر مخزونك الحقيقي. لذلك فحص قاعدة البيانات كان بنيوياً وقراءةً فقط بعد الترحيل؛ يجب إجراء اختبار قبول صغير بعد النشر قبل بدء الاستعمال اليومي.

## رفع الموقع إلى Netlify
1. حمّل ملف ZIP الخاص بالنشر.
2. افتح Netlify ثم صفحة الموقع، واسحب ملف ZIP إلى منطقة النشر اليدوي (Deploy manually / Drag and drop).
3. يجب أن يكون `index.html` في جذر الأرشيف، وهذا ما تم التحقق منه في هذه الحزمة.
4. بعد اكتمال النشر، افتح الموقع وحدّث الصفحة تحديثاً كاملاً؛ تم تحديث Service Worker إلى v20 لتجنب بقاء ملفات v19 في الذاكرة المؤقتة.
5. سجّل الدخول برمز ADMIN واختبر عرض Historique، ثم نفّذ سجل إنتاج تجريبياً بكمية صغيرة جداً من EP-3189، وتحقق من انخفاض الرصيد وظهور الحركة، ثم احذف السجل التجريبي من ADMIN وتحقق من عودة الرصيد وظهور RESTAURATION. لا تستخدم كمية كبيرة ولا تختبر على مخزون غير متاح.

ملف ZIP المخصص لNetlify يحتوي ملفات الموقع فقط؛ ملفات SQL ليست ضمن الأرشيف المنشور حتى لا تصبح ملفات قاعدة البيانات متاحة كملفات عامة على الموقع.

## تعديلات v19
- ربط Back / EP-3189 ببراميل `chemical_barrels` بدلاً من `paint_barrels`.
- حفظ حركة استهلاك EP-3189 كحركة `OUT` مرتبطة بمعرّف سجل الإنتاج والطبقة.
- عند حذف سجل إنتاج بواسطة ADMIN، تُسجّل حركة عكسية `ADJUSTMENT / INCREASE` مع الاحتفاظ بالحركة الأصلية، ويُسجّل حدث RESTAURATION.
- الاستهلاك السنوي وصافي المستهلك من البرميل يستبعدان الحركات التي تم عكسها.
- حفظ `production_extras` مع سجل الإنتاج والطبقات في معاملة واحدة؛ لم يعد هناك استدعاء ثانٍ قد يفشل بعد حفظ الإنتاج.
- حفظ الاستهلاك اليومي وتقسيم Diluant (Chimiste / Rouleaux / Pompes) عبر دالة واحدة ذرّية.
- حساب `weight_after_paint_kg` في قاعدة البيانات كـ Base + PRE + مجموع الطبقات. يبقى `production_weight_kg` = Base + PRE فقط.
- توحيد عرض Cabine 138 إلى 516.5 mm وPorte CF 100 إلى 562 mm بين الواجهة وقاعدة البيانات.
- إضافة VCM Cabine CF255 مع عرض 779 mm، حتى تتطابق قائمة VCM مع خيار VCM-Film Cabine CF255.
- إضافة Gestion des barils de peinture داخل Administrateur: إضافة وتعديل بيانات البرميل وحذفه فقط إذا لم يكن له أي تاريخ حركات؛ لا يمكن تغيير الوزن بعد بدء الاستهلاك.
- ترشيح PE-Film بحسب النظام ونوع القطعة Cabine/Porte، وإظهار VCM-Film حسب نوع VCM المختار.
- إظهار طبقات الإنتاج وكمياتها ومعاملاتها واسم المادة/رقم البرميل في Historique عند توافر صلاحية القراءة.
- إضافة Historique de consommation des matières chimiques داخل Administrateur مع Modifier / Supprimer / Imprimer؛ التصحيح لا يمحو الحركة القديمة، بل يسجل حركة عكسية وحركة جديدة عند التعديل، ويحدّث المخزون والمعاملات والاستهلاك السنوي.
- تنبيه المخزون عند 50 kg أو أقل.
- تسمية التبويب Administrateur، وإظهار `Rôle: ADMIN` للمسؤول فقط؛ لا تظهر عبارة `Utilisateur` ولا رسالة منع الإدارة في واجهة التطبيق. تبقى صلاحيات OPERATOR وVIEWER كما هي.
- إبقاء رمز ADMIN الحالي وآلية تعدد الأجهزة دون تغيير؛ سجل الرمز الحالي غير مربوط بمستخدم واحد، ودالة الدخول الحالية تسمح بإنشاء ملف مستقل لكل هاتف.
- تحديث Service Worker cache إلى v19.
- إضافة وظيفة ADMIN لتعديل طبقات سجل الإنتاج (نوع الطلاء / البرميل / الكمية) مع عكس الحركات السابقة وإضافة حركات جديدة دون حذف سجل الحركة القديم؛ يتم التعديل كمعاملة واحدة وتحديث الوزن بعد الطلاء والمعاملات.
- توسيع تحميل سجل استهلاك المواد الكيميائية وسجل الاستهلاك اليومي وسجل حركة البراميل باستخدام pagination بدلاً من سقف ثابت صغير.

## اختبارات مطلوبة بعد تنفيذ SQL
1. بحساب ADMIN أو OPERATOR، أنشئ سجلاً تجريبياً بكمية Back صغيرة من EP-3189.
2. تحقق من انخفاض رصيد البرميل بنفس الكمية، وظهور حركة OUT وسجل CONSOMMATION.
3. تحقق أن الوزن بعد الطلاء يساوي Base + PRE + مجموع الطبقات، وأن وزن الإنتاج المعتاد يظل Base + PRE.
4. بحساب ADMIN، غيّر نوع/برميل/كمية إحدى الطبقات في سجل تجريبي، ثم تحقق من عكس الحركة القديمة وإضافة الحركة الجديدة وتحديث المعامل والوزن.
5. بحساب ADMIN، احذف السجل التجريبي فقط. تحقق من عودة الرصيد، وظهور حركة RESTAURATION، وعدم احتساب الاستهلاك المعكوس في الاستهلاك السنوي.
6. اختبر حفظ استهلاك يومي مع تقسيم Diluant، وتأكد من أن السجل وتقسيمه يحفظان معاً أو يفشلان معاً.
7. اختبر PCM وPRINTING وVCM، وأنواع PE-Film وVCM-Film، خصوصاً VCM Cabine CF255 وVCM Porte.
8. اختبر الدخول بنفس رمز ADMIN على هاتفين مختلفين، وتأكد من ظهور نفس بيانات Supabase في كليهما.

## نقاط لم تُعتمد نهائياً قبل اختبار قاعدة البيانات
- تعديل النظام أو نوع bobine يظل منفصلاً عن تعديل الطبقات. عند تغيير النظام، يجب أولاً التأكد من أن الطبقات الحالية متوافقة معه؛ وإلا تُعدّل الطبقات أو تزال قبل تغيير النظام.
- اختبار فعلي عبر Supabase/Netlify لا يمكن إثباته بالفحص المحلي؛ يجب تنفيذ SQL أولاً في بيئة اختبار أو بعد أخذ نسخة احتياطية، ثم إجراء اختبار إنتاج تجريبي وحذفه بواسطة ADMIN للتحقق من الحركات العكسية.
- بعض عمليات إدخال/استهلاك/جرد براميل المواد الكيميائية ما زالت في تبويب Matières chimiques حتى لا تتغير صلاحيات OPERATOR الحالية؛ أما إدارة المنتجات وStock total والسنوي فقد أصبحت داخل Administrateur.
